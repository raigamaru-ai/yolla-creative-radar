# Weekly Creative Radar для Yolla

Ты выполняешь полный еженедельный цикл. Модули 1, 2 и публикацию делают скрипты, а модули 3 (анализ) и 4 (сценарии и промпты) пишешь ты сам. Работай без вопросов к пользователю: в облачном запуске отвечать некому. Если чего-то нет, отметь это в отчёте и продолжай.

Дата запуска — сегодня, окно — 7 предыдущих дней. Чтобы пересобрать прошлую неделю, добавь `--date YYYY-MM-DD` (это дата той пятницы) ко всем командам.

## 0. Подготовка

```bash
pip install -q -r requirements.txt
python -m radar doctor
```

Если `doctor` показывает ✗ по APIFY_TOKEN, GOOGLE_SERVICE_ACCOUNT_JSON или доступу к папке Drive, остановись. Итоговым сообщением напиши, что именно не настроено (см. README.md, раздел «Настройка»).

## 1–2. Сбор и скачивание (скрипт)

```bash
python -m radar prep
```

Команда идёт 10–40 минут: акторы Apify работают медленно. Запусти её в фоне или с большим таймаутом и дождись конца. Результат лежит в `work/<дата>/`:
- `creatives.csv`: все креативы, которые крутились в окне, с метриками и `score` (0–100);
- `manifest.json`: скачанные топ-креативы с кадрами (`frames`), транскриптом озвучки, текстом объявления и ссылками на Drive;
- `frames/*.jpg`: ключевые кадры (0.5с, 1.5с, 3с — это хук, дальше равномерно).

Если у одного конкурента ошибка, это нормально: работай с тем, что собралось. Если в таблице 0 креативов, всё равно сделай документ и объясни в нём почему (по логу `prep`).

## 3. Анализ: что сработало (пишешь ты) → `work/<дата>/analysis.md`

Как читать метрики:
- В Ad Library нет CTR и конверсий. Охват (`reach`) есть только у показов в EU/UK (DSA), у остальных он пустой.
- Главный прокси успеха — **долгожительство** (`days_running`): плохой креатив не крутят 30+ дней.
- Второй прокси — **вариации** (`variations`): сколько копий креатива запущено. Масштабируют то, что работает.
- `is_new_this_week = True` значит свежий тест. Это сигнал о том, куда идёт конкурент, а не доказательство успеха.

Процесс:
1. Открой `creatives.csv`: распределение по конкурентам и платформам, топ-20 по score, новые за неделю.
2. Для каждого креатива из `manifest.json` (до ~25 штук) **посмотри кадры** (Read на jpg), прочитай транскрипт, текст и CTA. Разложи каждый по схеме: хук в первые 3 секунды (тип: вопрос / боль / цена / эмоция / UGC-лицо / демонстрация экрана), герой (кто в кадре), сюжет, оффер, текст на экране, язык и гео, длительность, CTA, стиль (UGC / моушн / постановка / скринкаст).
3. Найди повторяющиеся паттерны в разных креативах и у разных конкурентов. Сравни сильные креативы (высокий score) со слабыми.

Структура `analysis.md`:

```markdown
## Что сработало у конкурентов на этой неделе
(8–12 поинтов, от сильного к слабому. В каждом: паттерн → доказательства: какие креативы [#rank, конкурент, дни, охват, вариации] → почему работает для аудитории международных звонков → сила сигнала: высокая/средняя/низкая)

## Что общего у сильных креативов
(хуки, длительность, герои, офферы, визуальный язык, язык и гео: короткими списками)

## По конкурентам
(Таблица: конкурент | креативов в окне | новых | главная ставка недели | лучший креатив со ссылкой)

## Новые тесты недели
(что конкуренты начали пробовать: свежие углы и офферы)

## Ограничения данных
(где нет охвата, какие акторы упали, сколько креативов без медиа)
```

У каждого упомянутого креатива ставь ссылку `library_url`. Где есть `drive_media_url`, ставь ссылку и на неё.

## 4. Сценарии и промпты для Yolla (пишешь ты) → `work/<дата>/scenarios.md`

Перед написанием прочитай `prompts/yolla_brief.md` (продукт, аудитория, тон, ограничения) и `prompts/video_models.md` (как писать промпты под каждую модель).

Сделай **5–6 сценариев**. Каждый опирается на 1–2 поинта из анализа (укажи их номера), но идея и исполнение оригинальные, под Yolla. Не копируй конкурентов: никаких их персонажей, слоганов, фирменных цветов и узнаваемых сцен. Распредели сценарии по разным типам: минимум один UGC/talking head, один эмоциональный «звонок домой», один про цену или выгоду, один демонстрационный (экран приложения), один на свежий тренд из «Новых тестов недели».

Структура `scenarios.md` (начинается с H1):

```markdown
# Yolla Creative Radar — <неделя: даты окна>

**Окно анализа:** … · **Креативов проанализировано:** N (FB: x, TikTok: y) · **Конкуренты:** …

## Главное за неделю
(5 буллетов: самые важные выводы и что делаем)

## Топ-10 креативов конкурентов
| # | Конкурент | Площадка | Дней | Охват | Вариаций | Новый | Хук (кратко) | Ссылка |

## Сценарии для Yolla

### Сценарий 1. <Название>
- **На чём основан:** поинты №… из анализа + креативы-примеры #…

- **Формат:** 9:16 · 15–25 с · FB Reels / TikTok · гео и язык
- **Хук (0–3 с):** …
- **Раскадровка:**

| Шот | Время | Что в кадре | Текст на экране | Озвучка/звук |
|---|---|---|---|---|

- **CTA:** …
- **Что измеряем:** hook rate (3s view), CTR, CPI

#### Промпты

**Шот 1 — <кратко>**

*Стартовый кадр (image prompt для Midjourney/Imagen, если нужен image-to-video):*
```
…
```
*Kling:*
```

```
*Seedance:*
```

```
*MiniMax:*
```
…
```
*Negative (где поддерживается):* `…`

**Референсы к шоту 1:**
![референс](frames/<имя_кадра>.jpg)
Что взять из референса: композицию / свет / ракурс / темп (одной строкой) · источник: <library_url>

(повтори для каждого шота)
```

Правила промптов и референсов:
- Каждый шот ≤ 10 секунд: так модели генерируют стабильно. Длинный сценарий = несколько шотов.
- Промпты пиши на английском, раскадровку и пояснения — на русском.
- В референсах используй **только реальные пути из `manifest.json` → `frames`**, относительно `work/<дата>/` (например `frames/003_Rebtel_fb_123_f1_0.5s.jpg`). Скрипт публикации вставит картинки в документ и добавит ссылки на Drive. Не выдумывай пути. Если подходящего кадра нет, опиши референс словами и дай поисковый запрос (Pinterest/Pexels).
- Референс у конкурента — это ориентир по композиции, свету и темпу, а не объект для копирования. Логотипы и персонажей конкурента не воспроизводим.
- Экран приложения Yolla генерировать не нужно: помечай `[вставить реальную запись экрана Yolla]`.
- Цены, «бесплатно», проценты и бонусы помечай `⚠️ проверить с маркетингом`, если их нет в брифе.

## 5. Публикация

```bash
python -m radar publish
```

Скрипт собирает `scenarios.md` + `analysis.md` в Google Doc «Yolla — сценарии и промпты — <дата>», а таблицу кладёт как Google Sheet «00 Таблица креативов» в ту же папку недели. Ссылки сохраняются в `work/<дата>/links.json`.

## Итог
