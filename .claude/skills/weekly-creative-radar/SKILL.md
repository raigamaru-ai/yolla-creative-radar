# Weekly Creative Radar для Yolla

Ты выполняешь полный еженедельный цикл. Модули 1, 2 и публикацию делают скрипты, а модули 3 (анализ) и 4 (сценарии и промпты) пишешь ты сам. Работай без вопросов к пользователю: в облачном запуске отвечать некому. Если чего-то нет, отметь это в отчёте и продолжай.

Дата запуска — сегодня, окно — 7 предыдущих дней. Чтобы пересобрать прошлую неделю, добавь `--date YYYY-MM-DD` (это дата той пятницы) ко всем командам.

## 0. Подготовка

```bash
python -m pip install -q -r requirements.txt
# в облачном окружении системный cryptography собран под другой Python — ставим свой
python -m pip install -q --ignore-installed cffi cryptography
python -m radar doctor
```

Если `doctor` показывает хоть один ✗ (Apify-токен или доступ к API, Google-авторизация, папка отчётов), остановись. Отправь в Telegram, что именно не настроено (`python -m radar notify --text "Yolla Creative Radar: прогон <дата> не выполнен — <причина и как исправить>"`), и тем же текстом закончи итоговое сообщение (см. README.md, раздел «Настройка»). Не обходи сетевые ограничения окружения. Строки с ⚠ (Kling, Telegram) не блокируют прогон.

## 1–2. Сбор и скачивание (скрипт)

```bash
python -m radar prep
```

Команда идёт 10–40 минут: акторы Apify работают медленно. Запусти её в фоне или с большим таймаутом и дождись конца. Результат лежит в `work/<дата>/`:
- `creatives.csv`: все креативы, которые крутились в окне, с метриками и `score` (0–100);
- `manifest.json`: скачанные топ-креативы с кадрами (`frames`), транскриптом озвучки, текстом объявления и ссылками на Drive;
- `frames/*.jpg`: ключевые кадры (0.5с, 1.5с, 3с — это хук, дальше равномерно).

Если у одного конкурента ошибка, это нормально: работай с тем, что собралось. Если в таблице 0 креативов, всё равно сделай документ и объясни в нём почему (по логу `prep`).

## 3. Анализ: что сработало (пишешь ты) → `work/<дата>/analysis.md`

Как читать метрики:
- В Ad Library нет CTR и конверсий. Охват (`reach`) есть только у показов в EU/UK (DSA), у остальных он пустой.
- Главный прокси успеха — **долгожительство** (`days_running`): плохой креатив не крутят 30+ дней.
- Второй прокси — **вариации** (`variations`): сколько копий креатива запущено. Масштабируют то, что работает.
- `is_new_this_week = True` значит свежий тест. Это сигнал о том, куда идёт конкурент, а не доказательство успеха.

Процесс:
1. Открой `creatives.csv`: распределение по конкурентам и платформам, топ-20 по score, новые за неделю.
2. Для каждого креатива из `manifest.json` (до ~25 штук) **посмотри кадры** (Read на jpg; у статичных креативов `format: image` кадр — сама картинка), прочитай транскрипт, текст и CTA. Статику разбирай отдельно: заголовок и текст на картинке, визуал (фото / иллюстрация / 3D), оффер, бейджи, композиция, CTA. Разложи каждый по схеме: хук в первые 3 секунды (тип: вопрос / боль / цена / эмоция / UGC-лицо / демонстрация экрана), герой (кто в кадре), сюжет, оффер, текст на экране, язык и гео, длительность, CTA, стиль (UGC / моушн / постановка / скринкаст).
3. Найди повторяющиеся паттерны в разных креативах и у разных конкурентов. Сравни сильные креативы (высокий score) со слабыми.

Структура `analysis.md`:

```markdown
## Что сработало у конкурентов на этой неделе
(8–12 поинтов, от сильного к слабому. В каждом: паттерн → доказательства: какие креативы [#rank, конкурент, дни, охват, вариации] → почему работает для аудитории международных звонков → сила сигнала: высокая/средняя/низкая)

## Что общего у сильных креативов
(хуки, длительность, герои, офферы, визуальный язык, язык и гео: короткими списками)

## По конкурентам
(Таблица: конкурент | креативов в окне | новых | главная ставка недели | лучший креатив со ссылкой)

## Статичные креативы
(если в топе есть статика: какие из них крутятся дольше всего и что у них общего — заголовки, визуал, офферы; если статики нет или она слабая, так и напиши)

## Новые тесты недели
(что конкуренты начали пробовать: свежие углы и офферы)

## Ограничения данных
(где нет охвата, какие акторы упали, сколько креативов без медиа)
```

У каждого упомянутого креатива ставь ссылку `library_url`. Где есть `drive_media_url`, ставь ссылку и на неё.

## 4. Сценарии и промпты для Yolla (пишешь ты) → `work/<дата>/scenarios.md`

Перед написанием прочитай `prompts/yolla_brief.md` (продукт, аудитория, тон, ограничения) и `prompts/video_models.md` (как писать промпты под каждую модель).

Обязательные правила из брифа:
- основной ценовой приём в большинстве сценариев — **«from $0.04 per minute»**;
- с декабря до ~10 января **минимум 2 сценария — праздничные** (Рождество и Новый год);
- приоритетные гео: Нигерия, Эритрея, Кения, Гана, Куба (для Кубы — креатив на испанском);
- палитра только белый и бирюзовый (`#4BCFD0` и оттенки), логотип — `assets/yolla-logo-*.svg`.

Сделай **5–6 сценариев**. Каждый опирается на 1–2 поинта из анализа (укажи их номера), но идея и исполнение оригинальные, под Yolla. Не копируй конкурентов: никаких их персонажей, слоганов, фирменных цветов и узнаваемых сцен. Распредели сценарии по разным типам: минимум один UGC/talking head, один эмоциональный «звонок домой», один про цену или выгоду, один демонстрационный (экран приложения), один на свежий тренд из «Новых тестов недели».

**Статика.** Если в анализе есть работающие статичные креативы конкурентов (раздел «Статичные креативы»), добавь после видеосценариев **3–4 концепта статичных креативов** для Yolla: описание, текст на картинке (заголовок, оффер, CTA, 2–3 варианта для A/B) и промпты для генерации. Если работающей статики у конкурентов нет, дай 1–2 концепта и напиши почему так мало.

Структура `scenarios.md` (начинается с H1):

```markdown
# Yolla Creative Radar — <неделя: даты окна>

**Окно анализа:** … · **Креативов проанализировано:** N (FB: x, TikTok: y) · **Конкуренты:** …

## Главное за неделю
(5 буллетов: самые важные выводы и что делаем)

## Топ-10 креативов конкурентов
| # | Конкурент | Площадка | Дней | Охват | Вариаций | Новый | Хук (кратко) | Ссылка |

## Сценарии для Yolla

### Сценарий 1. <Название>
- **На чём основан:** поинты №… из анализа + креативы-примеры #…
- **Гипотеза:** почему это сработает у аудитории Yolla
- **Формат:** 9:16 · 10–15 с · FB Reels / TikTok · гео и язык
- **Хук (0–3 с):** …
- **Раскадровка** (для понимания команды; промпт всё равно один на весь ролик):

| Время | Что в кадре | Текст на экране / субтитры | Речь, войсовер, звук |
|---|---|---|---|

- **CTA:** …
- **Что измеряем:** hook rate (3s view), CTR, CPI

#### Промпты (один на весь ролик)

*Стартовый кадр (image prompt, если нужен image-to-video):*
```
…
```
*Kling:*
```
<цельный промпт на весь ролик: таймкоды, реплики дословно, субтитры и текст на экране, Sound, Style, Avoid>
```
*Seedance:*
```
…
```
*MiniMax:*
```
… (если версия сокращённая — пометка, чего в ней нет)
```

**Референсы:**
![референс](frames/<имя_кадра>.jpg)
Что взять: композицию / свет / ракурс / темп (одной строкой) · источник: <library_url>

## Статичные креативы для Yolla

### Статика 1. <Название>
- **На чём основан:** статичные креативы конкурентов #… / поинты №…
- **Формат:** 1:1 и 4:5 (лента), 9:16 (сторис) · гео и язык
- **Визуал:** …
- **Текст на картинке:** заголовок / оффер / CTA — варианты A, B, (C)

*Промпт (Kling Image / Midjourney / Imagen / Seedream):*
```
…
```
**Референс:** ![референс](<путь к картинке конкурента из manifest.json>) · что взять · источник: <library_url>
```

Правила промптов и референсов:
- **Один ролик — один промпт** на каждую модель. Не дели ролик 10–20 с на 5-секундные шоты с отдельными промптами: смены планов описываются внутри промпта по таймкодам. Целевая длина — до 15 с. Ролик длиннее нужно пометить (см. `prompts/video_models.md`).
- **Речь и звук — в промпте.** Войсовер, диктор, реплики персонажей пиши дословно в промпт (кто говорит, язык, акцент, интонация), плюс музыка и фон. Модель генерирует звук сама, отдельной озвучки на монтаже нет.
- **Субтитры и текст на экране — в промпте.** Точный текст, стиль, место и момент появления. Цены и офферы пиши ровно как в брифе.
- Промпты пиши на английском, раскадровку и пояснения — на русском. Реплики, субтитры и текст на экране — на языке креатива (EN, для Кубы ES).
- В референсах используй **только реальные пути из `manifest.json` → `frames`**, относительно `work/<дата>/` (например `frames/003_Rebtel_fb_123_f1_0.5s.jpg`). Скрипт публикации вставит картинки в документ и добавит ссылки на Drive. Не выдумывай пути. Если подходящего кадра нет, опиши референс словами и дай поисковый запрос (Pinterest/Pexels).
- Референс у конкурента — это ориентир по композиции, свету и темпу, а не объект для копирования. Логотипы и персонажей конкурента не воспроизводим.
- Экран приложения Yolla генерировать не нужно: помечай `[вставить реальную запись экрана Yolla]`.
- Цены, «бесплатно», проценты и бонусы помечай `⚠️ проверить с маркетингом`, если их нет в брифе.

## 4б. Генерация в Kling (пишешь задания ты, генерирует скрипт)

Если в `config.yaml` стоит `kling.enabled: false` или `doctor` показал ⚠ по Kling, пропусти этот шаг (не пиши `kling_jobs.json`) и укажи это в итоге. Иначе напиши `work/<дата>/kling_jobs.json`:

```json
{"jobs": [
  {"id": "s1_video", "scenario": 1, "kind": "video", "aspect_ratio": "9:16", "duration": 15, "multi_shot": true, "audio": "native",
   "prompt": "Format: ... 0-3s: ... 3-9s: ... 9-15s: ... Sound: ... Style: ... Avoid: ..."},
  {"id": "s1_static", "scenario": 1, "kind": "image", "aspect_ratio": "1:1", "prompt": "..."}
]}
```

Правила:
- **Одно видео на сценарий** (до 6): промпт Kling из `scenarios.md` как есть (он уже цельный на весь ролик, ≤ 2500 символов), длина до **15 секунд**, `multi_shot: true`. Если в ролике есть речь, войсовер или музыка, ставь `"audio": "native"`.
- **Статика** (до 6): промпты из раздела «Статичные креативы для Yolla», текст на картинке — в промпте.
- Форматы только `9:16`, `1:1`, `16:9`. По умолчанию видео — `9:16` (Reels/TikTok), статика — `1:1` (лента). Для сценариев под YouTube/десктоп бери `16:9`. Разрешение 720p задаёт скрипт.
- Отрицательные указания пиши внутри промпта (`Avoid: text, logos, watermarks, orange, ...`): отдельного negative prompt у Kling 3.0 нет.
- Субтитры, текст на экране и речь — в промпте (модель делает их сама). Не проси рисовать логотип Yolla и экран приложения: под них оставляй место. Никаких логотипов и персонажей конкурентов.
- Палитра из брифа: `teal and white color palette, accents #4BCFD0`.

Затем:

```bash
python -m radar generate --dry-run   # проверка заданий и оценка стоимости
python -m radar generate             # 10–40 минут: отправка в Kling, ожидание, загрузка в Drive
```

Лимиты (число роликов, потолок units за прогон, длительность ≤ 15 с, форматы) заданы в `config.yaml → kling` и проверяются скриптом: лишние задания он пропустит. Результат: `work/<дата>/generated.json` и папка недели `03 Сгенерировано в Kling`. Раздел «Сгенерировано в Kling» с превью попадёт в документ сам. Если часть заданий упала, это не повод останавливаться.

## 5. Публикация

```bash
python -m radar publish
```

Скрипт собирает `scenarios.md` + `analysis.md` в Google Doc «Yolla — сценарии и промпты — <дата>», а таблицу кладёт как Google Sheet «00 Таблица креативов» в ту же папку недели. Ссылки сохраняются в `work/<дата>/links.json`.

Напиши `work/<дата>/telegram.md` — простой текст без Markdown-разметки (Telegram покажет её символами), до ~1500 знаков:

```

```
